Keunggulan Normalisasi 3NF: Pada skema awal skripsi (Hal. 72), tabel booking memuat kolom id_produk dan jumlah secara langsung (1 transaksi hanya bisa 1 barang). Melalui proses normalisasi (1NF → 2NF → 3NF), dibentuk entitas pemisah detail_booking sehingga pembeli dapat memesan aneka camilan (Kelanting, Untir-untir, Keripik Singkong) dalam 1 keranjang sekaligus tanpa anomali data.

Catatan Analisis Dosen Penguji / Akademik:
  • Anomali Skema Asli: Menempatkan id_produk dan jumlah di tabel booking melanggar kaidah First Normal Form (1NF) dan Second Normal Form (2NF) jika seorang pembeli ingin membeli lebih dari 1 macam camilan sekaligus. Hal ini mengakibatkan redundansi baris booking atau ketidakmampuan multi-item cart.
  • Solusi 3NF: Diciptakan entitas perantara detail_booking (Composite Table). Setiap item produk yang dibeli menjadi 1 baris di detail_booking yang mereferensikan 1 id_booking. Hal ini mendukung penuh sistem E-Commerce modern!

Interaksi Aktor Pelanggan & Administrator terhadap Batasan Sistem Informasi Pemasaran UMKM

2 Aktor • 12 Use Cases

Tabel Spesifikasi Use Case (Katalog Skenario Sistem)

ID Nama Use Case Aktor Deskripsi Singkat Pre-Kondisi & Post-Kondisi
UC-01 Registrasi & Login Pelanggan, Admin Pengguna membuat akun baru atau masuk menggunakan username dan password terdaftar. Pre: Form login/daftar terbuka.
Post: Sesi pengguna tersimpan sesuai level akses.
UC-02 Katalog & AJAX Live Search Pelanggan Melihat daftar produk makanan ringan dan mencari camilan secara instan tanpa reload halaman via AJAX. Pre: Produk berstatus 'tersedia'.
Post: Hasil pencarian dinamis tampil di layar.
UC-03 Kelola Keranjang Belanja Pelanggan Menambahkan camilan ke keranjang, mengubah kuantitas (qty), atau menghapus item sebelum checkout. Pre: Stok barang > 0.
Post: Keranjang diperbarui dan subtotal dihitung otomatis.
UC-04 Checkout Pemesanan Pelanggan Mengisi data alamat pengiriman, nama penerima, nomor telepon, dan membuat order booking resmi. Pre: Keranjang berisi minimal 1 item.
Post: Terbit kode unik booking (contoh: BK-20261105001).
UC-05 Bayar via Midtrans Snap Pelanggan Melakukan pembayaran otomatis menggunakan QRIS / Virtual Account bank dengan Snap pop-up modal. Pre: Booking tersimpan dan snap_token di-generate.
Post: Webhook notifikasi mengupdate status booking menjadi 'dibayar'.
UC-06 Transfer Manual & Bukti Pelanggan Mentransfer ke rekening resmi BRI UMKM dan mengunggah foto struk/bukti transfer melalui form. Pre: Kode booking terbit.
Post: Bukti tersimpan dengan status 'menunggu' verifikasi admin.
UC-07 Lacak Status Pesanan Pelanggan Memeriksa status pesanan menggunakan input kode booking tanpa harus login. Pre: Memiliki kode booking valid.
Post: Informasi status transaksi & resi ditampilkan.
UC-08 Kelola Data Produk Admin Operasi CRUD (Tambah, Edit, Hapus, Perbarui Stok & Foto) aneka produk makanan ringan. Pre: Login sebagai admin.
Post: Data produk di database termutakhirkan.
UC-10 Verifikasi Pembayaran Admin Meninjau foto bukti transfer pembeli, menyetujui transaksi (terverifikasi) atau menolak dengan catatan. Pre: Terdapat bukti transfer masuk.
Post: Status booking berubah menjadi 'dibayar'.
UC-12 Cetak Laporan Penjualan Admin Mencetak rekapitulasi penjualan dan total omset berdasarkan filter rentang tanggal. Pre: Terdapat transaksi booking 'dibayar' / 'selesai'.
Post: Print preview / PDF laporan siap cetak.

1. Tabel: pengguna (Autentikasi & Pengguna) PK: id_pengguna
Nama Field Tipe Data Null Key Default Keterangan

password VARCHAR(255) NO - NULL Kata sandi terenkripsi (Bcrypt hash)
no_tlp VARCHAR(15) YES - NULL Nomor telepon / WhatsApp
alamat TEXT YES - NULL Alamat tempat tinggal pembeli

created_at TIMESTAMP YES - CURRENT_TIMESTAMP Waktu registrasi akun
2. Tabel: produk (Katalog Makanan Ringan) PK: id_produk
Nama Field Tipe Data Null Key Default Keterangan
id_produk INT(11) NO PRI AUTO_INC Identifier unik produk
merk VARCHAR(100) NO - NULL Nama camilan (Kelanting, Untir-untir, Keripik)
harga INT(11) NO - NULL Harga jual satuan (Rupiah)
stok INT(11) NO - 0 Jumlah persediaan stok tersedia
deskripsi TEXT YES - NULL Deskripsi rasa & keunggulan camilan
status ENUM('tersedia','habis') NO - 'tersedia' Status ketersediaan produk
gambar VARCHAR(255) YES - NULL File gambar kemasan camilan
updated_at TIMESTAMP YES - CURRENT_TIMESTAMP Waktu terakhir produk diedit
3. Tabel: booking (Header Transaksi Pemesanan) PK: id_booking | FK: id_pengguna
Nama Field Tipe Data Null Key Default Keterangan
id_booking INT(11) NO PRI AUTO_INC Identifier unik pesanan
kode_booking VARCHAR(30) NO UNI NULL Kode unik faktur (BK-YYYYMMDDXXX)
id_pengguna INT(11) NO MUL NULL FK ke tabel pengguna(id_pengguna)
nama_penerima VARCHAR(100) NO - NULL Nama penerima paket pesanan
no_tlp_penerima VARCHAR(15) NO - NULL Nomor telepon penerima
alamat_pengiriman TEXT NO - NULL Alamat lengkap pengiriman paket
total_harga INT(11) NO - 0 Total nominal seluruh pesanan
status_booking ENUM(5 nilai) NO - 'menunggu_bayar' 'menunggu_bayar','dibayar','dikirim','selesai','batal'
snap_token VARCHAR(255) YES - NULL Token autentikasi Midtrans Snap Popup
metode_pembayaran ENUM('transfer_manual','payment_gateway') NO - 'transfer_manual' Pilihan metode bayar pembeli
tgl_booking DATETIME YES - CURRENT_TIMESTAMP Waktu transaksi dibuat
4. Tabel: detail_booking (Rincian Item Pesanan - 3NF) PK: id_detail | FK: id_booking, id_produk
Nama Field Tipe Data Null Key Default Keterangan
id_detail INT(11) NO PRI AUTO_INC Identifier unik baris item
id_booking INT(11) NO MUL NULL FK ke booking(id_booking) ON DELETE CASCADE
id_produk INT(11) NO MUL NULL FK ke produk(id_produk)
harga_satuan INT(11) NO - NULL Harga produk saat transaksi dilakukan
